## 1. Описание работы

Лабораторная работа посвящена детальному изучению и программной реализации иерархической структуры данных **«Бинарное дерево поиска» (Binary Search Tree, BST)**:

- **Класс `Node`:** легковесный узел дерева (`__slots__ = ("key", "left", "right")`).
- **Класс `BST`:**
  - `insert(key)` — итеративная вставка с сохранением инварианта BST; дубликаты игнорируются;
  - `search(key)` — итеративный спуск от корня со сравнением ключей;
  - `delete(key)` — удаление узла с корректной обработкой трёх канонических случаев:
    1. удаление листа (отцепление от родителя);
    2. удаление узла с одним ребёнком (подтягивание дочернего поддерева);
    3. удаление узла с двумя детьми (замена на преемника — минимальный ключ в правом поддереве — и удаление преемника).
  - **Четыре вида обходов:**
    - `in_order()` — рекурсивный симметричный обход ($L \to N \to R$), порождающий строго возрастающую последовательность ключей;
    - `pre_order()` — рекурсивный прямой обход ($N \to L \to R$) для сериализации и клонирования;
    - `post_order()` — рекурсивный обратный обход ($L \to R \to N$) для удаления/освобождения памяти снизу вверх;
    - `level_order()` — итеративный обход в ширину по уровням (BFS) с использованием двухсторонней очереди `collections.deque`.
  - **Характеристики структуры:**
    - `height()` — вычисление высоты дерева (число рёбер на самом длинном пути от корня к листу; пустое дерево = -1, корень = 0);
    - `size()` — подсчёт общего числа узлов дерева.
- **Верификация:**
  - `self_check()`: проверка граничных случаев (пустое дерево, один узел, удаление отсутствующих ключей);
  - проверка всех 3 случаев удаления на малом дереве;
  - проверка всех 4 обходов на каноническом дереве;
  - стресс-тестирование на 100 сериях случайных команд вставки и удаления со сверкой инварианта упорядоченности и совпадением с эталоном стандартной библиотеки Python (`set` + `sorted`);
  - проверка деградации на упорядоченных данных.
- **Бенчмарк производительности (Вариант 8):**
  - Экспериментальное сравнение времени $1\,000$ поисковых запросов в BST и в списке Python (оператор `in`) по методике бенчмаркинга (`docs/reproducibility.md`: прогрев, 5 повторов, медиана) для $N \in [1\,000, 3\,000, 10\,000, 30\,000, 100\,000]$.
  - Экспериментальное подтверждение деградации операций на упорядоченном потоке данных до $\mathcal{O}(n)$.
  - Построение комплексных графиков производительности и высоты дерева `lab05_graphs_variant8.png`.

## 3. Сводная таблица сложности операций BST

| Операция | Лучший случай | Средний случай (случайные ключи) | Худший случай (упорядоченные ключи) | Дополнительная память |
| :--- | :---: | :---: | :---: | :---: |
| **`search(key)`** | $\mathcal{O}(1)$ (в корне) | $\mathcal{O}(\log n)$ | $\mathcal{O}(n)$ | $\mathcal{O}(1)$ |
| **`insert(key)`** | $\mathcal{O}(1)$ (первый узел) | $\mathcal{O}(\log n)$ | $\mathcal{O}(n)$ | $\mathcal{O}(1)$ |
| **`delete(key)`** | $\mathcal{O}(1)$ | $\mathcal{O}(\log n)$ | $\mathcal{O}(n)$ | $\mathcal{O}(h)$ стек / $\mathcal{O}(1)$ |
| **`in_order()`** | $\mathcal{O}(n)$ | $\mathcal{O}(n)$ | $\mathcal{O}(n)$ | $\mathcal{O}(h)$ стек + $\mathcal{O}(n)$ список |
| **`pre_order()`** | $\mathcal{O}(n)$ | $\mathcal{O}(n)$ | $\mathcal{O}(n)$ | $\mathcal{O}(h)$ стек + $\mathcal{O}(n)$ список |
| **`post_order()`** | $\mathcal{O}(n)$ | $\mathcal{O}(n)$ | $\mathcal{O}(n)$ | $\mathcal{O}(h)$ стек + $\mathcal{O}(n)$ список |
| **`level_order()`** | $\mathcal{O}(n)$ | $\mathcal{O}(n)$ | $\mathcal{O}(n)$ | $\mathcal{O}(w)$ очередь $\le \mathcal{O}(n)$ |
| **`height()`** | $\mathcal{O}(n)$ | $\mathcal{O}(n)$ | $\mathcal{O}(n)$ | $\mathcal{O}(w)$ очередь BFS |
| **`size()`** | $\mathcal{O}(n)$ | $\mathcal{O}(n)$ | $\mathcal{O}(n)$ | $\mathcal{O}(w)$ очередь BFS |

*Обозначения:* $n$ — число узлов в дереве, $h$ — высота дерева ($h = \mathcal{O}(\log n)$ в сбалансированном дереве, $h = n - 1$ в вырожденном), $w$ — максимальная ширина дерева ($w \le \lceil n/2 \rceil$).
